# Proces van begin tot eind — toolversie 1.0.0

> Archief, niet meer uitvoerbaar vanaf een schone pc: de v1.0.0-release,
> assets en tag zijn verwijderd. Het downloadcommando in de tabel werkt niet
> meer. De [E2E-handleiding voor release 3.0.0](e2e-command.md)
> beschrijft de nieuwe lichte export en een beschikbare wheel. De oudere
> 2.0.0-wheel heeft die functie niet.

Historisch voorbeeld voor macOS/zsh met de destijds publieke wheel. De tabel
beschrijft de oude volgorde, maar is door het ingetrokken downloadbestand niet
meer vanaf een schone pc uitvoerbaar. `$RUN_DIR` is één door de tool gemaakte
runmap; bij hervatten moet dit **dezelfde** map blijven. Bestandsnamen onder
`artifacts/` beginnen met een wisselende tijdstempel. Alle runtimegegevens
blijven buiten de repository. Een nieuwe bronmomentopname kan andere
aantallen dan de historische 289.916 → 119.801 opleveren.

| Stap | Commando | Verwachte output: bestand en betekenis |
|---|---|---|
| 1. Mappen kiezen | `TOOL_DIR="$HOME/company-harvest-tool"`<br>`DATA_DIR="$HOME/Documents/company-harvest-data"`<br>`mkdir -p "$TOOL_DIR" "$DATA_DIR"`<br>`cd "$TOOL_DIR"`<br>`export COMPANY_HARVEST_DATA_DIR="$DATA_DIR"` | `$TOOL_DIR/` voor de installatie en `$DATA_DIR/` voor alle lokale runs; nog geen bronverkeer. Zorg voor voldoende schijfruimte voor volledige bronarchieven. |
| 2. Release-wheel ophalen | `curl -fL -o company_harvest-1.0.0-py3-none-any.whl 'https://github.com/pcvantol/company-harvest/releases/download/v1.0.0/company_harvest-1.0.0-py3-none-any.whl'` | `$TOOL_DIR/company_harvest-1.0.0-py3-none-any.whl`: installeerbaar pakket, geen brondata. |
| 3. Download controleren | `shasum -a 256 company_harvest-1.0.0-py3-none-any.whl` | Alleen console-output; verwachte SHA-256: `c8847f5cd0f6b03f0829b93f8ecaf3a569c1bcc1392250f0713b03538ac8552c`. Stop bij afwijking. |
| 4. Installeren | `python3.14 -m venv .venv`<br>`.venv/bin/python -m pip install ./company_harvest-1.0.0-py3-none-any.whl`<br>`CH="$TOOL_DIR/.venv/bin/company-harvest"`<br>`"$CH" --version` | `$TOOL_DIR/.venv/`: geïsoleerde installatie; de laatste opdracht toont `1.0.0`. Geen checkout, Git of GitHub-login nodig. |
| 5. Hostcheck | `"$CH" doctor` | JSON op het scherm met onder meer `ready`, Python, schijfruimte en datamap; geen nieuw outputbestand. Ga niet door bij `ready=false`. |
| 6. Run aanmaken | `RUN_DIR="$("$CH" run init --target 10000 --print-path)"`<br>`printf '%s\n' "$RUN_DIR"` | `$RUN_DIR` is bijvoorbeeld `$DATA_DIR/runs/<run-id>`. Daarin ontstaan `run.json` (config/status), `state.sqlite3` (journal), `artifacts/`, `evidence/` en `logs/`. `--target 10000` garandeert geen 10.000 matches. Bewaar de geprinte absolute mapnaam. |
| 7. Run-preflight | `"$CH" run preflight --run-dir "$RUN_DIR"` | JSON op het scherm met `ready=true` als de lokale run gereed is; geen nieuw outputbestand. |
| 8. Bronnen downloaden, samenvoegen, dedupliceren en vóór KVK filteren | `"$CH" run prepare-pre-kvk --run-dir "$RUN_DIR"` | Sequentiële volledige IND-, GLEIF-, ANBI- en DUO-inname; geen Wikidata of KVK-verzoek. `artifacts/*_02_source_*_companies.csv` plus bronrapporten en `evidence/` bevatten de ruwe bronkandidaten en bronbewijs. `artifacts/*_03_pre_kvk_master.tsv` + `*_03_pre_kvk_report.json` bevatten de verliesvrij gededupliceerde master/closure. `*_03_pre_kvk_eligible.tsv` is de KVK-invoer; `*_03_pre_kvk_excluded.tsv` bewaart uitgesloten rijen en redenen; `*_03_pre_kvk_filter_metadata.json` bevat criteria, aantallen en hashes. Pas bij geslaagde volledige brongates bestaan deze complete bestanden. |
| 9. Voorbereiding auditen | `"$CH" audit verify --run-dir "$RUN_DIR"` | JSON `valid=true` op het scherm bij intacte geregistreerde bron-/filterartefacten; geen apart auditbestand. Een fout eerst onderzoeken. |
| 10. KVK-configuratie controleren | `"$CH" kvk preflight --run-dir "$RUN_DIR" --provider public-http` | `artifacts/*_04_kvk_capability_preflight.md`: lokale configuratie-/capabilitystatus (`IMPLEMENTED` of `CAPABILITY_MISSING`). Deze opdracht doet geen live netwerkverzoek en bewijst dus geen bereikbaarheid of bulktoestemming. |
| 11. Optionele kleine proef | `"$CH" kvk pre-kvk-batch --run-dir "$RUN_DIR" --limit 10 --interval 2` | Maximaal tien nieuwe frontendverzoeken. `artifacts/*_04_pre_kvk_kvk_batch_matches.tsv`, `*_04_pre_kvk_kvk_batch_outcomes.tsv` en `*_04_pre_kvk_kvk_batch_report.json` zijn **PARTIAL**; het SQLite-journal onthoudt de aanvragen. Dit is nog geen input voor consolidatie/export. Sla deze stap over als u meteen de rustige doorloop wilt beginnen. |
| 12. Rustig verwerken en hervatten | `"$CH" kvk pre-kvk-run --run-dir "$RUN_DIR" --max-requests 100 --interval 2`<br>Herhaal **hetzelfde commando met dezelfde runmap** voor volgende groepen. | In de runhoofdmap: `pre_kvk_kvk_progress.json` (totaal, journalstatussen, resterend aantal), `pre_kvk_kvk_matches.tsv` (bevestigde matches) en `pre_kvk_kvk_unresolved.tsv` (geen/technisch onzekere match). `state.sqlite3` is leidend. Per uitvoering maximaal 100 nieuwe aanvragen, minimaal twee seconden tussen requeststarts; een blokkade stopt eerder. Ctrl+C bewaart een lopende aanvraag als onzeker, niet als stil opnieuw te verzenden. |
| 13. Voortgang en hervatting na nieuwe terminal | `python3.14 -m json.tool "$RUN_DIR/pre_kvk_kvk_progress.json"`<br>Na een nieuwe terminal: `CH="$HOME/company-harvest-tool/.venv/bin/company-harvest"` en `RUN_DIR="<eerder geprint absoluut runpad>"`; herhaal stap 12. | Alleen console-output. Ga pas verder bij `status: COMPLETE`, `remaining: 0` en geen actieve toegangs-/rateblokkade. `COMPLETE` betekent gesloten kandidatenjournal, **niet** dat iedereen een KVK-match kreeg. Een 401/403/429 niet met nieuwe run of providerwissel omzeilen. |
| 14. KVK-artefacten auditen | `"$CH" audit verify --run-dir "$RUN_DIR"` | JSON `valid=true` als de geregistreerde COMPLETE-match- en unresolved-bestanden bij alle KVK-kandidaten en hashes passen; geen apart bestand. |
| 15. Op KVK-nummer canoniseren | `"$CH" kvk consolidate --run-dir "$RUN_DIR"` | `artifacts/*_05_kvk_companies_canonical.csv`: één onderbouwd record per uniek KVK-nummer; `*_05_kvk_canonical_conflicts.csv`: tegenstrijdige providervelden. Kan niet op uitsluitend de PARTIAL-batch uit stap 11. |
| 16. Eenmanszaken scheiden | `"$CH" companies exclude-sole-proprietorships --run-dir "$RUN_DIR"` | `artifacts/*_06_non_sole.csv`, `*_06_sole_excluded.csv`, `*_06_legal_form_review.csv`: respectievelijk toegelaten rechtsvormen, bevestigde eenmanszaken, onbekende/niet-gemapte rechtsvormen. |
| 17. Actieve bedrijven scheiden | `"$CH" companies active-only --run-dir "$RUN_DIR"` | `artifacts/*_07_active.csv`, `*_07_inactive_excluded.csv`, `*_07_status_review.csv`: actieve, inactieve en onbekende/niet-gemapte status; bronstatus wordt niet stil geraden. |
| 18. Strikte eindexport | `"$CH" export --run-dir "$RUN_DIR" --limit 10000` | **Alleen bij nul unresolved**: `artifacts/*_08_delivery_outputset/` met `companies_delivery.csv` en `.xlsx` (exact naam + KVK), `companies_delivery_full.csv` en `.xlsx` (volledige velden), `companies_reserve.csv` en `outputset_manifest.json` (hashes). Bij unresolved stopt de opdracht zonder output. `--limit` is een maximum, geen garantie op 10.000. |
| 19. Alternatief: bewuste partiële export | `"$CH" export --run-dir "$RUN_DIR" --limit 10000 --allow-partial` | Gebruik dit **in plaats van stap 18** wanneer unresolved bewust worden geaccepteerd. Dezelfde outputsetbestanden, geregistreerd als `PARTIAL`; mogelijk minder dan 10.000 of nul records. Dit is niet het volledig gevalideerde doelresultaat. Bekende v1.0.0-fout: `audit verify` meldt daarna ten onrechte `MISSING_REQUIRED:outputset_manifest` doordat het een PARTIAL-manifest niet als nieuwste COMPLETE-artefact opzoekt. Claim hiervoor geen audit-PASS. |
| 20. Rapportage | `"$CH" report --run-dir "$RUN_DIR"` | `artifacts/*_08_outcome_report.json` (bronopbrengst, dedup, closure, resources) en `*_08_run_report.md` (leesbaar overzicht). `Alle input verwerkt` in dit rapport blijft false bij unresolved, ook wanneer het requestjournal gesloten is. |
| 21. Eindaudit en bestanden openen | `"$CH" audit verify --run-dir "$RUN_DIR"`<br>`open "$RUN_DIR/artifacts"` | Na **strikte** export: JSON `valid=true` als alle integriteitscontroles slagen; Finder toont de tijdgestempelde outputset. Na **partiële** export: verwachte v1.0.0-fout uit stap 19, dus niet als succesvolle eindaudit presenteren. |

Deze procedure toont wat de tool kan uitvoeren. Een volledige live
KVK-doorloop, passende gebruiksvoorwaarden en een resultaat van 10.000
actieve, geverifieerde bedrijven zijn voor v1.0.0 niet bewezen.
