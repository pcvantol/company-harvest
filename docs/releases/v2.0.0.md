# Company Harvest 2.0.0

Deze release wordt gebouwd uit de onveranderlijke broncommit van tag
`v2.0.0`; de volledige commit-SHA, wheelhash en assetgroottes staan in het
meegeleverde `distribution-manifest.json`. De wheel is een zelfstandige
Python-CLI en vereist geen checkout, GitHub-login of Codex tijdens gebruik.

## Installatie

Dit is een incompatibele wijziging ten opzichte van v1.0.0: alleen Python
3.14.x wordt nog ondersteund, niet Python 3.11–3.13. Installeer de wheel na downloaden in
een nieuwe virtuele omgeving; afhankelijkheden worden online door pip
opgehaald.

macOS:

```sh
python3.14 -m venv .venv
.venv/bin/python -m pip install ./company_harvest-2.0.0-py3-none-any.whl
.venv/bin/company-harvest --version
```

Windows PowerShell:

```powershell
py -3.14 -m venv .venv
.venv\Scripts\python.exe -m pip install .\company_harvest-2.0.0-py3-none-any.whl
.venv\Scripts\company-harvest.exe --version
```

## Nieuw sinds 1.0.0

- Eén expliciet `run e2e`-commando verbindt de volledige vierbronneninname,
  conservatieve deduplicatie, pre-KVK-filter, publieke KVK-frontendcheck,
  rechtsvorm-/statusfilters, export, rapport en audit. `--limit-kvk-check N`
  begrenst de vaste, hervatbare KVK-cohort; `--all-kvk` kiest bewust de hele
  toegelaten lijst. `--export-limit` blijft afzonderlijk standaard 10.000.
- Partiële outputsets krijgen een echte audit van het nieuwste manifest, de
  status en alle bijbehorende bestanden; de v1.0.0-foutmelding
  `MISSING_REQUIRED:outputset_manifest` bij geldige partiële export is
  opgelost. Onopgeloste kandidaten vereisen expliciet `--allow-partial`.
- Nieuwe run-/artefactnamen gebruiken de leesbare UTC-prefix
  `yyyy.mm.dd_hhMMss`; oude runs blijven leesbaar. Alle CLI-commando's tonen
  recordvrije, optioneel gekleurde voortgang en veilige fouten op stderr;
  machineleesbare stdout blijft behouden.
- De macOS-/Windows-CI-matrix draait uitsluitend op Python 3.14, gebruikt
  Node-24-gebaseerde Actions en bevat een afzonderlijke offline E2E-proef
  met gemockte KVK-resultaten. De interne CLI-/pre-KVK-refactor behoudt
  bestaand gedrag.

## Belangrijke grenzen

Installatie of starten voert geen harvest uit. `run e2e` gebruikt de publieke
KVK-frontend, nooit de betaalde API; het minimuminterval van twee seconden is
geen garantie op toegang of toestemming voor grootschalig gebruik. Een
401/403/429 of andere blokkade stopt de run zonder omweg. Een geslaagde
offline E2E-test bewijst geen actuele bereikbaarheid van bronwebsites of KVK.
De volledige pre-KVK-lijst is niet live door KVK verwerkt en een gevalideerde
lijst van 10.000 actieve bedrijven is niet opgeleverd. `--limit-kvk-check N`
kan dus slechts een deelresultaat leveren; `--all-kvk` is geen garantie dat
iedere kandidaat een match krijgt. Stap 9, het samenvoegen met een externe
lijst, blijft een afzonderlijk offline commando. Wikidata wordt niet in de
vierbronnenworkflow gebruikt.

Zie [de E2E-handleiding](../functional/e2e-command.md) voor uitvoeren,
hervatten, outputbestanden en de betekenis van `PARTIAL`.
